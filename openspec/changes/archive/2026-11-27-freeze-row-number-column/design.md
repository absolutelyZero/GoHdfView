# Design

## Context

见 proposal.md - Why。当前 `internal/view/table_view.go` 的 `dataGrid` 把表头与所有数据行放进同一个 `ui.ScrollBoth` 滚动容器：表格首列（行号列，`gridCol{gutter: true}`）与其他数据列并列作为普通列。表头已用 `.Sticky().Top(0)` 在纵向滚动时固定，但行号列没有对应的横向固定处理，横向滚动时会随数据列一起移出视野。

数值表、字符串表、复合表与读取失败占位表都通过 `dataGrid` 绘制，因此冻结行为集中在 `dataGrid` 一处即可覆盖全部表格形态。参见 specs/dataset-data-view/spec.md 的行为要求。

## Goals / Non-Goals

**Goals:**

- 让行号列在横向滚动时固定在表格左侧、始终可见。
- 冻结行为对所有经由 `dataGrid` 绘制的表格一致生效。
- 保持既有纵向滚动、表头固定、翻页、分页、坐标定位与读取策略不变。
- 不增加进程内存占用，不改变按页读取数据的策略。

**Non-Goals:**

- 不冻结行（纵向）以外的表头之外的其它行，也不冻结数据列或列头之外的列。
- 不新增行号列显示格式、列宽可调或用户可切换的冻结设置。
- 不修改 `github.com/egoist/mygo/ui` 上游。

## Decisions

### 决策 1：在 `dataGrid` 内实现左冻结，而非改动每个调用方

- **选择**：把冻结逻辑收敛到 `dataGrid`，所有调用方（数值表、字符串表、复合表、失败占位表）自动获得一致行为。
- **理由**：行号列在 `dataGrid` 中对应固定的首列（`col == 0` / `gutter: true`），是唯一需要冻结的列；调用方只提供 `cell(row, col)` 内容回调，不应感知布局细节。
- **备选**：在每个表格构造函数里各自拼装冻结结构 —— 被否，会重复逻辑且容易遗漏。

### 决策 2：优先使用 `ui` 包提供的横向 sticky 能力

- **选择**：与表头 `.Sticky().Top(0)` 对称，对行号列使用 `ui` 元素提供的左侧 sticky 定位（例如 `.Sticky().Left(0)` 或等价的 API），使行号列的表头单元格与每个数据行单元格相对滚动容器固定在左侧。
- **理由**：复用框架既有机制，改动最小，且与表头固定方式一致，避免重复实现滚动偏移计算。
- **验证（任务 1.1 结论）**：已确认项目锁定的 `github.com/egoist/mygo/ui v0.10.0` 提供左向 sticky —— `ui/sticky.go` 中定义 `func (e *node) Sticky() *node`，配合 `.Left(0)` / `.Right(0)` / `.Top(0)` / `.Bottom(0)` 设置对应轴 inset；源码注释明确举例「the check box choosing all the rows at the left of a table scrolling sideways」，并说明支持双层叠加（子级相对横向滚动容器 sticky、父级相对纵向滚动容器 sticky），且 sticky 元素绘制在兄弟节点之上。可复现核对：读取 https://api.github.com/repos/egoist/mygo/git/blobs/7118bbebf972d9051661bca215e1f5356f33697c 中的 `ui/sticky.go`。**结论：采用本决策 2 的主方案（`.Sticky().Left(0)`），任务 2.4 备选重构不适用。**
- **备选**：手动把行号列拆出滚动容器、用两个同步滚动的区域拼装 —— 仅在 `ui` 包无左向 sticky 时采用，因为需要额外维护纵向滚动同步，复杂度明显更高。

### 决策 3：保留 `cell(row, col)` 回调签名与数据索引

- **选择**：不改变 `dataGrid` 的对外签名，行号列仍由 `col == 0` 分支生成，数据列索引仍为 `row*cc + (col-1)`。
- **理由**：冻结是纯视觉/布局变化，不应影响数据读取、分页与数值格式化。
- **备选**：把行号列移出回调、单独渲染 —— 会改动所有调用方，扩大改动面，不采用。

### 决策 4：冻结列与数据列之间保持视觉分隔

- **选择**：在冻结行号列右侧保留/补一条细分隔线（与现有 `ColLine` / `ColRowLine` 一致的描边风格），使滚动的数据不会从冻结列下方透出造成混淆。
- **理由**：冻结列叠在滚动内容之上时，需要明确边界提示当前列从何处开始。
- **备选**：无分隔线 —— 滚动到底时数据紧贴行号，可读性差，不采用。

## Risks / Trade-offs

- [风险] `ui v0.10.0` 可能没有左向 sticky API，或 sticky 在嵌套 `ui.Row` / `ui.ScrollBoth` 中的行为与预期不符 → 缓解：实现前用最小测试确认 API 与行为；若不可用，采用决策 2 的备选（拆分冻结列与滚动区并同步纵向滚动）。
- [风险] 冻结列叠加在数据列之上，横向滚动时数据可能从冻结列下方透出 → 缓解：为行号列设置不透明背景并在右侧加分隔线（决策 4）。
- [风险] 表头与行号列交叉的左上角单元格需要同时满足「纵向 sticky」与「横向 sticky」 → 缓解：确认 `ui` 支持双向 sticky 叠加；否则在备选方案中单独固定左上角单元格。

## Migration Plan

- 本变更为纯 UI 行为变更，无数据迁移。
- 实施后通过 `internal/view/table_test.go` 的测试验证：行号列在横向滚动场景下的可见性与数据列 unaffected；运行 `go test ./...` 回归。
- 回滚：撤销 `dataGrid` 的冻结改动即可恢复原行为。
