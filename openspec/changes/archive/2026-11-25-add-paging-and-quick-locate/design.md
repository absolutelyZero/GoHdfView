# Design

## Context

数据视图已有分页状态 `TableState.RowPage / ColPage / Fixed`：行分页步长 100、列分页步长 50，秩大于 2 时固定前导维、表格只展开最后两维（见 `internal/view/table.go`）。读取请求由 `requestFor` 把页号换算成切片起点与长度，再经页缓存命中或异步读取。

当前 `internal/view/table_view.go` 的 `pager` 把行页信息、列范围与「左侧列 / 上一页 / 下一页 / 右侧列」放在同一条底栏内，方向混杂且没有按坐标跳转的入口。UI 工具包提供 `ui.TextInput`、`ui.Select`、`GhostButton` 等控件，足以实现新的底栏与定位输入。

设计稿 `ui/ui.pen` 的 A 方案已按本变更调整：底栏左侧为行（上下）分页，右侧为列（左右）分页，中部为「定位 D0 [ ] D1 [ ] 跳至」。

## Goals / Non-Goals

**Goals:**

- 底栏在视觉与交互上明确区分行分页与列分页，并保持现有分页步长与页缓存行为不变。
- 支持按完整坐标（前导固定维 + 行下标 + 列下标）一步定位到对应页。
- 定位失败时给出非模态提示，且不改变当前页。

**Non-Goals:**

- 不改变 HDF5 读取接口、分页尺寸常量或页缓存容量。
- 不新增表内单元格跳转、书签或历史记录。
- 不调整未分页场景（标量、单列字符串表）的既有呈现逻辑，仅沿用新的底栏分区。

## Decisions

### 决策 1：底栏拆成左右两个分区，方向与位置一一对应

把 `pager` 拆成三个部件并按「行分页 — 定位 — 列分页」排列，两侧用弹性空白撑开：

- 左侧只放行方向控件：上行/下行按钮 + 行范围（如 `0–99 / 10000`）。
- 右侧只放列方向控件：列范围 + 左列/右列按钮。
- 列数不超过一页时，右侧列分页控件不展示，左侧行分页保持可用。

替代方案是继续单行排列但在按钮文案上区分方向；该方案在窄窗口下仍会把两个方向挤在一起，未采用。

### 决策 2：快速定位采用逐维输入，坐标长度等于数据集秩

- 输入框数量等于 `TableLayout.Rank`，秩为 2 时即 D0（行）与 D1（列）；秩大于 2 时前 `Rank-2` 个输入对应被固定的前导维。
- 确认后把输入解析为 `[]uint64`：校验长度等于秩、每个值小于对应 `Dims[i]`；前导维写入 `Table.Fixed`，行下标除以 100 得到 `RowPage`，列下标除以 50 得到 `ColPage`。
- 秩超过 4 时，逐维输入会使底栏过宽，改为单个「逗号分隔」文本输入，解析规则相同。

替代方案是始终使用单个 `行,列` 文本；它在秩大于 2 时无法表达前导维坐标，未采用。另一个替代方案是弹窗表单，因其打断浏览且设计中无弹窗层，未采用。

### 决策 3：仅当目标页与当前页不同时才推进代数

定位前比较目标 `(RowPage, ColPage, Fixed)` 与当前状态；完全相同时只清空提示、不增加 `gen`，避免缓存失效和重复读取。发生变化时才 `gen++`，沿用现有的过期结果丢弃机制。

### 决策 4：定位错误内联展示，不阻塞浏览

越界、空值、非整数、负数都视为定位失败：保持当前页与输入内容，在定位输入旁显示一行提示（指明越界的维度或「坐标必须是整数」），不使用模态弹窗，与「错误提示不阻塞浏览」保持一致。

## Risks / Trade-offs

- [高秩数据集输入过多导致底栏拥挤] → 秩大于 4 时退化为单个逗号分隔输入，保证底栏宽度可控。
- [用户把坐标理解为「页号」而非「元素下标」] → 输入前缀标出 D0/D1 轴名，提示文案使用「下标」，并在范围文案中显示当前页覆盖的起止下标。
- [定位与异步读取竞态] → 复用 `gen` 过期判定：定位改变页号即递增代数，迟到的旧结果被丢弃。
- [逐维输入与键盘遍历冲突] → 输入框只在获得焦点时接收文本，Enter 触发定位，Esc 放弃本次输入。

## Migration Plan

无数据或接口迁移。上线即生效；若需回滚，恢复 `pager` 的单行实现并移除定位控件即可，分页状态字段保持不变。

## Open Questions

- 行分页是否需要 PageUp / PageDown 快捷键，可留待后续变更处理，不影响本设计。
