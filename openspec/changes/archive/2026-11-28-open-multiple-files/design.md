# Design

## Context

当前 `open-multiple-files` 实现采用“每文件一个 `document` + 文档标签栏 + 活动镜像”的模型，与 HDFView 的统一对象树交互不一致。需求是：所有已打开文件作为顶层节点出现在同一棵树中，选中节点决定右侧显示的文件。动机与范围见 proposal.md，行为见 specs delta。

## Goals / Non-Goals

**Goals:**
- 用一棵统一对象树容纳多个文件，选中节点即切换数据来源。
- 每个文件的树展开、选中、读取缓存与分页状态保持独立。
- 打开/关闭/去重语义清晰，句柄及时释放。

**Non-Goals:**
- 不做每文件标签栏（移除已实现的标签交互）。
- 数据表拖出为独立窗口由另一个变更处理，不在本设计范围。
- 不改变 HDF5 只读约束，不新增第三方依赖。

## Decisions

1. **统一多根 Source。** 扩展 `internal/view.Source`：新增 `Roots() []*hdf5.Node`（或等价的多根接口），由组合 Source（multiSource）维护“文件根节点 → 所属文档”的映射；`App.SetSource` 支持一次设置多个根，树的 `roots`/展开/选中统一在一份 `view.App.Tree` 状态中。理由：HDFView 式统一树的核心是一棵树多个根；单份树状态天然避免“活动文档”与“选中对象”双状态同步问题。备选（保留多棵树 + 标签切换）与需求冲突，不采用。
2. **按节点路由读取与描述。** 组合 Reader/Meta 根据选中节点的 ID 找到所属文档并委托其 `ReadSlice`/`Info`；`hdf5.Node` 已有指向 `Document` 的字段，可据此建立归属映射。理由：统一树下同一 `view.App` 要服务多个文件，读取层必须按节点归属分派；保持上层表格/图像调用不变。
3. **当前文件由选中节点派生。** 去掉 `docs []*document`/`active int`/活动镜像；`refreshTitle`、`statusBar`、`setError` 等通过“当前选中节点 → 所属文件”取得文件名与句柄。理由：选中节点是唯一事实来源，避免两套状态不一致。
4. **打开与去重。** `openFile(path)` 规范化路径（Clean + Abs）比较；已打开则把树选中定位到该文件根节点并展开，不重复加载；否则 `hdf5.Open`，失败保留当前状态并经非模态提示，成功把其根加入统一树。命令行多个参数依次加入，最后一个成为选中文件。理由：与现有去重与失败保留语义一致。
5. **关闭语义。** 基于当前选中节点确定所属文件：释放其句柄、从组合 Source 与树根集合移除、刷新选中到剩余文件；无剩余文件回到空状态。理由：Ctrl+W 的语义从“关闭标签”改为“关闭选中文件”，符合 HDFView 操作直觉。
6. **状态与失败隔离。** 每文件的读取缓存与分页键包含文件标识，互不串扰；某文件读取失败只影响其选中对象，其它文件节点仍可正常浏览。理由：统一树不意味着共享数据状态。
7. **回调装配。** 单个 `view.App` 在 `main()` 中一次性注入 `SetAsync`/`SetInvalidate`/`SetCSVExporter`（回退到改造前的单 App 装配）；文件句柄生命周期由 main 的文件集合管理。理由：统一树只有一个 App，无需每文档装配。

## Risks / Trade-offs

- [多根树的节点 ID 冲突] → 不同文件的 HDF5 对象头地址可能相同；`NodeID` 需附加文件标识参与去重与索引键（或在组合层加文件前缀）。
- [组合 Reader 路由错误] → 建立明确的“节点 → 文档”归属映射并在测试中按文件断言读取目标。
- [关闭文件后残留选中引用] → 关闭时先清除选中再移除根节点，刷新树状态。
- [测试环境无窗口] → 统一树逻辑通过注入假 Source/Reader 与新 Tester 测试验证。

## Migration Plan

无磁盘数据迁移：本次会回退已实现的标签模型并改为统一树，纯内存/交互层变更；升级后单文件行为不变。
