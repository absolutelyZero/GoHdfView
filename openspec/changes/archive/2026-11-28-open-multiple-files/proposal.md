# Proposal

## Why

当前实现把每个文件做成独立的文档标签页（左侧顶部一行 tab），这与 HDFView 的交互习惯不一致：HDFView 把所有已打开的文件作为对象树里的顶层节点，用户在同一棵树里展开、选中，选中哪个节点就查看哪个文件的数据。多标签方案还带来标签栏占用空间、文件数多时拥挤、以及“当前活动文档”与“当前选中对象”两套状态需要同步的问题。

本变更把多文件交互调整为与 HDFView 一致：**一棵统一的对象树，多个文件作为顶层根节点**，选中哪个文件下的节点，右侧工作区就显示哪个文件的数据。数据表可拖出为独立窗口用于多窗口对比的诉求，另立变更处理，不在本变更范围内。

## What Changes

- 取消“每个文件一个标签页”的左侧标签栏；改为所有已打开 HDF5 文件作为顶层节点出现在同一棵对象树中。
- 打开文件（菜单 / 快捷键 / 拖放 / 命令行参数）= 把一个文件作为根节点加入统一对象树；重复打开同一路径定位到已有根节点，不重复加载。
- 选中树中任一节点，右侧工作区显示该节点所属文件的数据（数据/元数据/属性、表格/图像、分页随节点与文件而定）。
- 关闭文件 = 从树中移除该文件的根节点并释放句柄；关闭最后一个文件回到空状态。提供基于当前选中节点的关闭操作。
- 窗口标题、状态栏反映当前选中节点所属文件；某个文件读取失败不影响树中其它文件的浏览。
- 保留只读约束；单文件使用场景行为不变。

## Capabilities

### New Capabilities

- 无（多文件能力归属现有 viewer-shell）

### Modified Capabilities

- viewer-shell: 修改「打开文件的方式」「菜单与快捷键」，并把“多文档标签页”需求替换为「统一对象树中的多文件」。

## Impact

- internal/view: `Source` 支持多根节点；读取/描述按选中节点所属文件路由；树状态（展开/选中）统一由一份状态承载。
- main.go: 去掉 `docs []*document`/`active` 标签模型与左侧标签栏；维护文件集合并按选中节点派生当前文件；打开/关闭/标题/状态栏/关闭操作围绕统一树改写。
- 无新增第三方依赖；沿用现有树控件、对话框与拖放机制。
- 兼容性：单文件使用场景行为不变；以标签切换文件的旧交互被统一树取代。
